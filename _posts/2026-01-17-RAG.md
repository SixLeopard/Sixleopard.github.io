Chunking strategy
This is where most RAG systems live or die. Cover the basics:

Fixed-size chunks (e.g., 500 tokens with 50-token overlap) — simple, works surprisingly well
Recursive splitting — splits on paragraph, then sentence, then word, preserving structure
Semantic chunking — splits where embedding similarity drops; more sophisticated, more expensive
Document-aware — for code, markdown, or HTML, split on natural boundaries (functions, headers)


Start with recursive character splitting at ~500 tokens with ~50 token overlap. Tune later if retrieval feels off.

Step 4 — Retrieval
The query side is shorter than the ingest side.
python# query.py

def retrieve(conn, question: str, k: int = 5) -> list[tuple[str, str]]:
    q_emb = embed(question)
    rows = conn.execute(
        "SELECT source, content FROM chunks "
        "ORDER BY embedding <=> %s::vector "
        "LIMIT %s",
        (q_emb, k),
    ).fetchall()
    return rows

OperatorDistance<->L2 (Euclidean)<#>Negative inner product<=>Cosine distance

Step 5 — Generation
Compose a prompt that gives the LLM the retrieved context and tells it how to behave.
pythonPROMPT = """You are a helpful assistant. Answer the question using ONLY the
context below. If the context doesn't contain the answer, say you don't know.

Context:
{context}

Question: {question}

Answer:"""

def generate(question: str, chunks: list[tuple[str, str]]) -> str:
    context = "\n\n---\n\n".join(f"[{src}]\n{txt}" for src, txt in chunks)
    prompt = PROMPT.format(context=context, question=question)

    r = requests.post(f"{OLLAMA_URL}/api/generate",
                      json={"model": "llama3.1:8b",
                            "prompt": prompt,
                            "stream": False})
    r.raise_for_status()
    return r.json()["response"]

What goes wrong (and how to fix it)
The honest section that separates a tutorial from a marketing post.
"It retrieves the wrong chunks"

Inspect what's being retrieved (print the top-k chunks before generation)
Check your chunking — chunks that are too big drown the signal, too small lose context
Try a stronger embedding model (mxbai-embed-large, bge-m3)
Add a reranker (see "next steps")

"Answers are vague or wrong even when retrieval looks good"

Generation model is too small — try a 13B+ model if hardware allows
Prompt is too loose — be more prescriptive about grounding and refusal
Context is too long — most local models degrade well before their advertised context window

"Ingest is slow"

Parallelize embedding calls
Batch your inserts
Consider a faster embedding model

"pgvector queries are slow"

Make sure the HNSW index is being used (EXPLAIN ANALYZE is your friend)
Tune hnsw.ef_search at query time
Add a WHERE clause filter? Make sure pgvector's filter handling matches your version
